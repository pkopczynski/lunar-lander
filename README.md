# Lunar Lander

A minimal 2D Lunar Lander built in **Godot 4.7.2** with GDScript, targeting **browser (Web) export**.

This repo is a playground for the whole game-making process: trying mechanics and gameplay, then building, deploying, publishing, and running the game live. Features are added in small, playable increments. This README is the shared context for AI agents generating new features; keep it current when a rule, convention, or constraint changes. Commit messages, PR titles, versioning and releases follow `CLAUDE.md`.

## Current state

Every run opens on the Office, a retro green-on-black Terminal where the player picks a ship type, browses Transport offers and accepts them as Contracts and starts loading them, and checks the Bank account. Contracts are flown down to the pad, unloaded and paid out into the Bank account. Then a scrolling two-area world: a surface with gravity, mountains and a landing pad, and gravity-free deep space with a maze-like station to dock in. Fuel, ship weight (with a Load that counts toward it), and refuelling on the pad and at the station. Domain terms are defined in `GLOSSARY.md`. Not yet set up: Web export preset, deployment, publishing, any live/production tooling.

## Gameplay rules

Tuning values are constants at the top of each script: world layout in `world.gd`, station shape in `station.gd`, per-ship values in `ship_type.gd`, rules shared by every ship type in `lander.gd`, camera in `camera.gd`. Those files are the source of truth for the numbers.

- **World:** a 2000 px wide column. From the bottom: the ground, the surface (with gravity), the border ~2270 px above the pad, deep space (no gravity, ~2600 px tall), and the station, which spans the full width and forms the ceiling.
- **Camera:** follows the lander with smoothing and stays inside the world. Zoom is 1.0 at ≤ 50 px/s, easing out to 0.65 at ≥ 400 px/s.

- **Controls:** in flight, Left/Right rotate, Up thrusts along the lander's nose (both ignored for a moment after a border crossing, see Border), R restarts in deep space (any time, including after a crash; in debug builds, R on the Surface only puts the ship back on the pad, see Restart). In the Office, Left/Right (and Up/Down) move between the main screen's tiles, Left/Right browse Ship offers or move between popup buttons, Up/Down move between Transport offers and their ACCEPT buttons, or between Contracts and START LOADING, Right/Left move between the Transport offers screen's columns, Return opens, selects or confirms, Escape counts as No in a popup, closes the Transport offer under the cursor, returns to the main screen from any other screen, and closes the Office from the main screen. Arrows, Return and Escape use Godot's built-in `ui_*` actions; `restart` is a custom action bound by physical key.
- **Office:** every run opens on the Office: a full-window Terminal (black, green outlines and text in the Silkscreen pixel font, a border, scanlines) with the header `ORBITAL FREIGHT CO. // ` plus the screen's name, and a key hint for the screen at the bottom (arrows in a hint are drawn, Silkscreen has no arrow glyphs). The game's version (e.g. `V0.1.0`) sits dimly at the right end of the key hint row.
  - **Main screen** (`// OFFICE`): every opening of the Office lands here. Three tiles in a row, SHIP SELECTION, TRANSPORT OFFERS and BANK ACCOUNT; the selected one is inverted, and movement stops at both ends. Return opens a tile; Escape on any other screen comes back here with the same tile selected. Escape here powers the Terminal off and leaves the current ship Docked (the Sparrow at run start).
  - **Ship selection** opens on the ship type in service (the one in the parking spot), tagged IN SERVICE. It shows one Ship offer at a time: name, flavour line, a wireframe picture of the hull, TANK in kg, SEATS, CARGO (the full-Tank cargo with no passengers) and MAX CAPACITY (the maximum capacity) in kg, THRUST and HANDLING as 5-block bars, and a `< n/N >` indicator. Browsing wraps at both ends. Return on another Ship offer opens "ARE YOU SURE?" (Yes selected; the selected button is inverted). Yes puts that ship type Docked in the parking spot with a full Tank and its default dry mass, and returns to the main screen; No or Escape returns to the same Ship offer. Return on the IN SERVICE Ship offer just returns to the main screen.
  - **Transport offers** lists the Transport offers (up to 7) in its left column and the Contracts in its right one. Each row shows its number (`#001`, numbered through the run), title, PASSENGERS, CARGO or PASSENGERS + CARGO, and the time left to accept it as m:ss. Rows alternate between two faint green tints. Return on a row opens the offer's details under it (passengers, cargo, deadline, trader and value, labels green and values white, with an ACCEPT button at their bottom right), on a slightly stronger tint, growing open over ~0.15 s (what isn't uncovered yet isn't drawn), and Return again closes them, shrinking them back the same way (the offer counts as closed at once: its ACCEPT is no longer a stop, and reopening grows the details from where they were); several offers can be open at once, and opening or closing one leaves the others. One cursor moves with Up/Down (stopping at both ends) through each offer's row, followed by its ACCEPT when it's open; the selected row or ACCEPT is inverted. Opening or closing an offer leaves the cursor on its row. When the list is taller than its area it scrolls just enough to keep the cursor's row or ACCEPT in view (on an open offer whose ACCEPT is dimmed, the row with its details, as much as fits), and small drawn ▲/▼ markers just right of the list's top and bottom show when more lies above or below; rows and lines that don't fit wholly in the area aren't drawn. The tints, animation time and marker size are constants in `office.gd` and `expandable_list.gd`. Escape on an open offer's row or ACCEPT closes that offer and puts the cursor on its row; anywhere else it returns to the main screen. An offer the ship can't take (counting the Contracts) has its text dimmed (row, reason and details; the cursor's highlight stays bright on it), with `NOT ENOUGH PASSENGER SEATS` or `OVERLOADED` (its cargo would pass the maximum capacity) under its row, and its ACCEPT is dimmed and skipped by the cursor; fuel never disables an offer. An offer that fits but would, on top of the Contracts, leave room for less than a full Tank stays lit and acceptable, with a red `FUEL LIMITED` note under its row. Return on an ACCEPT asks "ARE YOU SURE?" (Yes selected) for that offer only; Yes makes that offer a Contract, which leaves the list (nothing takes its place at once). Confirming checks again that the offer is still there and still fits. An open offer that expires just closes; if its ARE YOU SURE? was showing, that closes too, nothing is accepted and `OFFER EXPIRED` shows at the bottom left for 2 s. The right column lists CONTRACTS (`#006 TITLE`), then `PASSENGERS X/Y`, `CARGO X/Y KG` (accepted cargo over the full-Tank cargo for the accepted passengers), `FUEL LIMITED: X/Y KG` when the Contracts' Load leaves room for less than a full Tank (the fuel cap over the Tank), `DELIVER WITHIN m:ss` (the shortest Deadline among the Contracts) and `TOTAL VALUE €N` (the sum of their rewards), both hidden while there are no Contracts, and a START LOADING button, dimmed (and doing nothing) without Contracts; Return on it starts loading (see Loading). Summary labels are green and values white; once the cargo passes the full-Tank cargo the CARGO value turns red, and FUEL LIMITED shows, all red, at exactly that moment. Cargo beyond the full-Tank cargo, up to the maximum capacity, can still be accepted. Right moves focus to the Contracts column, on START LOADING (open offers stay open; the list's row is then outlined), Left moves it back. There, Up/Down move through the Contracts and then START LOADING (stopping at both ends); each Contract has a plain `X` at the right end of its row, on the same baseline as its text, and the selected Contract's whole row is inverted, and START LOADING is inverted only while it holds the cursor. Return on a Contract asks "REMOVE CONTRACT?" (No selected); No or Escape keeps it, Yes removes it for good: no payout, no transaction, its seats and cargo are freed, and it doesn't return to the offers. The cursor then stays on a Contract while any are left, otherwise on START LOADING. Contracts stay accepted when offers expire and when the player leaves the Office; once loading starts they can't be removed.

  Transport offers come from the Economy. A run starts with 5. While fewer than 7 are listed, a new one arrives after a random 30–90 s (the wait pauses while 7 are listed and is drawn afresh when it runs again). Each one expires 180–600 s after it appears (offer timers run everywhere, Office open or not). Offers leave the pool only by expiring or being accepted, and neither brings a new one at once. Generated offers are ⅓ passengers only, ⅓ cargo only, ⅓ mixed, with 1 to the largest ship type's seats and 500 kg to the largest cargo capacity in 100 kg steps, so some won't fit a smaller ship; nothing makes sure one fits. Deadline 60–180 s; reward €150 per passenger and €60 per 1 000 kg of cargo at a 120 s deadline, × (120 / deadline)^0.5, × a random 0.7–1.3. The pool sizes and arrival interval live in `economy.gd`, the other numbers in `transport_offer.gd`.
  - **Bank account** shows `PILOT` and `BALANCE €0` (label green, amount white): the balance in EUR, held by the Economy node and starting at €0 every run (a negative one reads `-€120`), then, a row's height below, one transaction per delivered Contract, newest first, its row showing only the payout: `#004 MINING SUPPLIES  CARGO  €544`. A Contract that paid €0 still gets one. The transactions work like the Transport offer list (`ExpandableList`), without buttons: alternating row tints, Up/Down move the cursor (stopping at both ends, the selected row inverted), Return opens or closes the transaction's details on the stronger tint with the same opening and closing animation, several can be open at once, the list scrolls to keep the cursor's row in view, with its details when it's open (as much as fits) with ▲/▼ markers, and Escape on an open transaction closes it (anywhere else it returns to the main screen). Open details show, labels green and values white: `BASE VALUE €640`, `PENALTY -€96 (12 S OVERDUE)` (Silkscreen has no `−` glyph, so it's a hyphen) or `PENALTY €0` when delivered on time, `PAYOUT €544`, `DEADLINE m:ss` (the flight's deadline the penalty was counted against: the shortest among its Contracts, which can be shorter than this Contract's own) `DELIVERED IN m:ss` (from the end of loading to landing on the pad, whole seconds rounded down) and `SHIP SPARROW` (the ship type in service when it was settled).

  The world is paused while the Office is showing. The Terminal powers on with a ~0.3 s CRT effect (a dot stretches into a bright line, which opens into the picture) and powers off with the reverse; the flight view shows only once power-off is over, and Office input is ignored during the effect. The "ENTER THE OFFICE?" popup over the flight view opens and closes without it.
- **Start:** once the player leaves the Office, the lander (the Sparrow unless another ship type was chosen) is Docked in the centre of the station's parking spot (re-picked at random each run), facing up, at rest, with a full tank. The pad is a destination only: fly out of the maze and down to the surface to land there.
- **Ship types:** each ship type has its own hull, flame, default dry mass, Maximum weight, Tank, passenger seats, cargo capacity, thrust, fuel burn and turn rate. Thrust and burn are given at the reference mass. The Sparrow: 10 000 kg default dry mass, 22 000 kg Maximum weight, 5 000 kg Tank, 4 seats, 8 000 kg cargo capacity, 150 px/s² thrust, 250 kg/s burn, 3.0 rad/s turn rate. The Halo: a C-shaped ring 40 px across with a 16 px hole, open at the nose (concave hull, gap included in the collision shape), flame at the back; 14 000 kg default dry mass, 32 000 kg Maximum weight, 8 000 kg Tank, 10 seats, 11 000 kg cargo capacity, 214 px/s² thrust, 231 kg/s burn, 2.2 rad/s turn rate (climbs off the pad at ~80% of the Sparrow's rate, and a full tank lasts ~1.2× as long as the Sparrow's). The Mule: a 42×68 px box with its two nose corners rounded to 4 px (back corners square), long axis along the thrust, flame on the short side at the back; 20 000 kg default dry mass, 41 000 kg Maximum weight, 12 000 kg Tank, 4 seats, 16 000 kg cargo capacity, 316 px/s² thrust, 207 kg/s burn, 1.5 rad/s turn rate (climbs off the pad at ~60% of the Sparrow's rate, and a full tank lasts ~1.4× as long as the Sparrow's). Each Maximum weight is the highest total at which that ship type still hovers and reaches the border crossing speed (`tests/test_*.gd` check this by adding a Load that brings a full ship to it). At full seats and cargo, every ship type has room for less than a full Tank. Each ship type's cargo capacity is its maximum capacity, the hard limit; its full-Tank cargo, the most cargo that still leaves room for a full Tank, is Maximum weight − dry mass − Tank − passengers × 80 kg, kept within 0 and the maximum capacity: Sparrow 7 000 kg, Halo 10 000 kg, Mule 9 000 kg with no passengers. Thrust-time targets are ratios to the Sparrow's measured full-tank thrust time (~24 s; its nominal Tank / burn is 20 s), not absolute seconds; `tests/test_halo.gd` and `tests/test_mule.gd` check them that way.
- **Mass:** total mass = dry mass (always the ship type's default) + fuel + Load (the passengers and cargo carried, 0 until loading finishes). Maximum weight caps the total: the fuel cap is min(Tank, Maximum weight − dry mass − Load), and refuelling, on the pad and at the station, stops there. The factor `w = total / 15 000 kg` divides thrust acceleration and scales gravity by half as much (`1 + 0.5·(w−1)`). Fuel burn is multiplied by its own factor, which counts the Load at half its mass: `(dry mass + fuel + 0.5·Load) / 15 000 kg`, so a loaded ship burns more gently than its weight alone would give, and a ship without a Load burns at `w`. Both factors change live as fuel burns or refills. Maximum weight is chosen so every ship type can still hover and cross the border.
- **Fuel:** thrust burns fuel (scaled by the burn factor above); a default full ship without a Load empties the tank in ~20 s of thrust. Burn is ×2 for the first 1 s after lifting off the pad (not after undocking), and up to ×2 more when thrusting against the motion (scaled by how directly, and by speed up to 150 px/s). At 0 fuel the engine doesn't fire.
- **Border:** gravity fades smoothly to zero over the 200 px below the border and is zero above it. Deep space flight is pure Newtonian: thrust is still divided by `w`, and there's no drag. Crossing the border either way needs ≥ 150 px/s vertical speed. A slower ship is sprung back to the side it came from. A real crossing shakes the screen for 2 s, starts steering until the ship is 150 px past the line, and disturbs the ship: for 0.6 s at 150 px/s down to 0.3 s at ≥ 400 px/s (by speed at the crossing), Left/Right and Up are ignored while the nose wobbles 4 times (each up to half the largest turn either way) and settles on a random lasting turn, either way, of up to 12° at 150 px/s down to 3° at ≥ 400 px/s (never under a third of that). The velocity turns with the nose, keeping its speed, so the path bends by the same lasting angle; nothing eases back. A ship sprung back by the border isn't disturbed. The numbers are the `DISTURB_*` constants in `lander.gd`.
- **Steering:** the game only damps the ship's speed and pushes it back; it never turns the ship. The nose stays where the player aimed it, and Left/Right and thrust work as in normal flight (apart from the border's disturbance). After a border crossing, speed is damped to 100 px/s.
- **Sides:** below the mountain tops, the mountains wall both sides and touching them crashes the ship. Above them, both sides are soft walls: within 150 px of an edge, sideways speed toward the edge is damped, the ship is pushed back inward, keeping its rotation, and it can never pass the edge.
- **Station:** a straight 100 px entry corridor leads from the station's bottom face into a vertical shaft. Three arms branch left and three right, like two back-to-back E letters. On each run, one of the six arm endings, picked at random, holds a chamber with the 120×136 px parking spot (cyan outline). Touching any station wall crashes the ship.
- **Docked** needs the whole ship inside the parking spot, at ≤ 40 px/s, while not thrusting. It then behaves like Landed: the ship zeroes velocity, eases upright, refuels after 2 s, and shows "Docked!". While docked, Left/Right turn the ship in place so it can face the way out. Up undocks it. The ship must leave the spot before it can dock again.
- **Loading:** START LOADING powers the Terminal off and starts loading over the flight view. Fuel above the fuel cap for the Contracts' Load is pumped out at once. The ship stays Docked and held (Up doesn't undock, Left/Right don't turn it, no cancelling) while the message counts down `Loading… 7s`; loading takes 3 s + 1 s per passenger + 1 s per 1 000 kg of cargo. Meanwhile it refuels as when resting, from the first frame (no 2 s delay), up to that cap, with `Refueling…` under the countdown. When it finishes, the Load is added to the ship's mass, the hold is released (refuelling carries on up to the cap), and the message shows `Loaded! Deliver within 1:30`, plus `Fuel limited to 3 680 kg` when the cap is below a full Tank, until the ship undocks. The delivery clock starts the moment loading finishes, even if the ship stays Docked; its Deadline is the shortest among the Contracts. Docking again while loaded shows no popup, so no Contracts can be added.
- **Unloading:** becoming Landed on the pad while delivering (a real landing or the debug pad shortcut) starts unloading by itself; the delivery clock stops and the HUD timer goes. The message counts down `Unloading… 4s` (2 s + 0.5 s per passenger + 0.5 s per 1 000 kg of cargo). Lift-off is blocked (Up does nothing), but refuelling goes on as usual, up to the fuel cap while the Load is aboard. Only the first landing counts: a ship that settles back, or lands again, doesn't unload twice.
- **Payout:** when unloading finishes, each Contract is settled on its own for the whole seconds overdue at landing (rounded down, like the red counter): it loses 2% of its passenger reward and 1% of its cargo reward per second, each part never below €0. The total goes into the Bank account, one transaction per Contract is added, and a small green `+€420` rises above the ship and fades over 2 s. The Load and the Contracts are cleared, the fuel cap is a full Tank again (refuelling carries on), and the ship can lift off.
- **Ship swap:** every time the ship docks (not at run start, not on the pad, not while loaded), a popup over the flight view asks "ENTER THE OFFICE?" with No selected. Until the ship is released it's frozen: Up doesn't undock, Left/Right don't turn it, and the refuel timer doesn't run; R still restarts (the station is in deep space). No or Escape closes the popup and refuelling starts after the usual 2 s. Yes opens the Office on the main screen. Choosing another ship type in Ship selection puts it Docked in the same parking spot; the station isn't rebuilt. While there are Contracts, ship swapping is locked: Ship offers other than the one in service show `SHIP LOCKED: CONTRACTS ACCEPTED` and Return on them does nothing (browsing still works). Leaving the Office (Escape on the main screen) releases the ship as No would, whether or not it was swapped.
- **Judged on every touchdown:** the result is decided the moment the lander touches the ground. Nothing can save a bounce.
- **Landed** needs all of these at touchdown:
  - vertical speed within its limit
  - horizontal speed within its limit
  - tilt from upright within its limit (angle is wrapped, so any number of full spins doesn't count)
  - lander center within the pad
- **Crashed** is any other touchdown, or touching the mountains or the station.
- **Landed:** the lander turns green, zeroes its velocity, eases upright over 0.3 s and rests (no gravity, no rotation). After 2 s it refuels at half a Tank per 6 s up to the fuel cap, showing "Refueling…". Up lifts off at any time (except while unloading), cancelling refuelling. A ship too heavy to climb just settles back, which counts as another landing.
- **Crashed:** physics stops, the lander turns red, and the label shows "Crashed!" plus "Press R to retry". A crash is final.
- **HUD:** right edge, a vertical fuel bar showing how full the current ship type's Tank is, with a brown, wavy, eased fill (frame flashes red when empty), "FUEL" above, total mass in kg below. While delivering, `DELIVERY 1:23` (the time left, m:ss) in the upper right, switching to a red `OVERDUE +0:12` (whole seconds late) that keeps counting.
- **Restart** reloads the whole scene, so every run starts from the scene's initial state: back on the Office main screen with the Sparrow, a €0 balance, a new Transport offer pool numbered from `#001`, and the parking spot re-picked. In debug builds (a testing shortcut), R on the Surface (below the border, whether flying, Landed or Crashed) instead puts the ship Landed on the pad, upright and at rest, keeping its ship type, dry mass, fuel and Load; the crash clears. In deep space, and always in release builds, R restarts.
- **Backdrop:** two Tatra-like ridges drawn behind the Surface, with no collision: a farther, jagged High Tatra ridge peaking at the mountain tops near Rysy, and a nearer, rounded ridge with Giewont's sleeping knight. Each is filled with the background gradient, darkened (`FAR_RIDGE_DARKENING`, `NEAR_RIDGE_DARKENING` in `world.gd`). They're fixed in the world (no parallax); the mountains cover their ends.
- There is no win state: the Bank account balance is the only measure of a run, and a crash ends it. You can fly between the station and the pad, docking and landing as often as you like.

Deliberately not built yet: a score or high-score table, HUD readouts (speed, altitude), terrain generation, sound, explosions, multiple levels.

## Constraints

- **Compatibility renderer only** (`gl_compatibility`). Godot's Web export supports only this renderer; keep it when changing project settings.
- **Godot-native nodes and GDScript only.** No external assets except bundled OFL fonts (see ADR 0001), and no addons or GDExtensions; shapes are drawn with `Polygon2D` or `_draw`.
- **Stay minimal:** the smallest change that makes a feature playable. Add a new scene or script only when one file genuinely stops being readable.
- **Read screen size at runtime** with `get_viewport_rect()`. The window uses `canvas_items` stretch with `expand` aspect, so the visible area changes with window shape.

## Code conventions

- Tuning values are `UPPER_SNAKE` constants at the top of the script, grouped by topic. The ship types (`ShipType.SPARROW`, `MULE`, `HALO`, `ALL`) are named like constants too, but are `static var`s because GDScript can't build objects in a `const`; never reassign them (tests may append a temporary entry to `ALL` and remove it again).
- Node references are `@onready var` with typed `$Path` lookups.
- Static typing everywhere (`:=`, typed parameters and return values).
- Comments only for non-obvious reasons (see the `move_and_slide()` note in `lander.gd`).

## Gotchas

- `move_and_slide()` removes the velocity pushing into the ground, so the impact velocity is saved *before* the call. Any new touchdown rule must read that saved value.
- Any collision with something other than `Ground` (mountains, station) is a crash; only ground contacts go to landing judgement.
- The parking spot has no collider either; docking checks that every hull vertex is inside the spot's `Rect2`.
- The station's walls are the station block minus the union of passage rectangles (`Geometry2D`). The entry cut reaches below the block so that the result is one polygon with no holes. Keep passages overlapping when changing the layout.
- The pad has no collider; landing is judged against the ground collider, and the "on the pad" check compares x positions. The pad's position comes from the current location (`World.location.pad_center_x`, from the `Location` table), never a constant: the drawn pad, the "on the pad" check and the debug pad shortcut all read it, and `World.change_location()` moves the drawn pad. Its size is still `PAD_WIDTH`/`PAD_HEIGHT` in `lander.gd`. The pad only appears at runtime, because the World's `_ready()` builds its shape.
- `Station` must stay above `Lander` in `main.tscn`: siblings become ready in order, and the Lander's `_ready()` reads `station.parking_spot` to place the docked start.
- The Office pauses the whole tree (`get_tree().paused`) while showing; only the Office (process mode Always) handles input then. R is handled by the Lander, so it does nothing while the Office is showing. `SceneTree.paused` survives a scene reload; the new Office sets it again in `_ready()`. Anything that must keep running behind the Office (the Economy) needs process mode Always too. Keep economy state in scene nodes (no autoload, no static state), so a restart wipes it.
- The Lander's `_ready()` still makes it a Docked Sparrow behind the Office; choosing a Ship offer calls `start_docked(type)` again. `start_docked()` never asks to enter the Office; only `dock()` does, by emitting `docked_at_station`. The Office answers with the "ENTER THE OFFICE?" popup and calls `lander.hold()`, which freezes `_physics_process`; the Lander doesn't know why it's held. No, and leaving the Office from the main screen, call `release()`; the refuel delay starts over because docking zeroed it and a held ship doesn't count it down. Choosing a ship type calls `start_docked(type)`, and entering Docked releases the hold. `start_loading()` releases it too: a loading ship isn't held but rests (so it refuels), with `loading` blocking lift-off and turning.
- The Lander's `state` (Flying, Landed, Docked, Crashed) changes only through `enter()`, which starts every state fresh: not held, no lift-off burn, docking armed, leveling stopped, with the state's colour and message. `start_docked()`, `reset_to_pad()` and `fly_from()` also move the ship and clear any border bounce, steering or disturbance. `enter()` also clears the `status` line. `rest()` rewrites the message every frame (title, `status`, then Refueling…), so outside text such as the loading and unloading countdowns must go through `show_status()`, which also shows it right away (keeping the Refueling… line) for a held ship (held ships don't rest). `lift_off_blocked` is set from outside like `held`, but `enter()` doesn't clear it, so a ship that settles back onto the pad while unloading stays grounded; the Economy clears it when unloading finishes. `lift_off()` is the only transition that looks at the state it leaves (the lift-off burn from the pad, no re-docking from the spot). Crashed and held make `_physics_process` return early; Landed and Docked skip gravity and judging. Restart is handled in `_unhandled_input`.
- Leveling after a landing lifts the corner that touched down, so the level tween ends with a `move_and_collide()` back onto the ground.

## Running and validating

Godot isn't on `PATH`; the editor binary is `~/Downloads/Godot.app/Contents/MacOS/Godot`.

- **Play:** open the project in the editor and press F5.
- **Import / parse check:** `Godot --headless --path . --import`
- **Smoke run** (prints any script errors): `Godot --headless --path . --quit-after 600`
- **Tests:** `Godot --headless --path . --fixed-fps 60 -s tests/run_tests.gd` runs every test and exits non-zero if any fails. In a fresh checkout, run `--import` first. `--fixed-fps 60` makes each frame one physics step without waiting for real time; the tests count physics frames, so they give the same results without it, just slower.
  - The runner loads every `tests/test_*.gd` and calls each `test_*` method on a fresh main scene. A test fails if a `check` fails, if no checks ran, or if any script error is logged while it runs.
  - Every run opens on the Office, so a test that flies calls `await choose_ship()` (or `choose_ship(ShipType.MULE)` etc.) first: from the main screen it opens Ship selection with `open_ship_selection()`, browses to that Ship offer with `browse_to(type)`, presses Return and confirms Yes (the ship type in service needs no Yes), then presses Escape to leave the Office, leaving the ship Docked. Office tests read `office()`: `showing`, `screen` (`Office.Screen`), `tile_labels()`, `selected_tile()`, `popup_text()`, `selected_ship_offer()`, `ship_offer_lines()` (the Ship offer's text, ratings as ■/□ blocks), `ship_offer_picture()`, `in_service_shown()`, `popup` (`Office.PopupKind`, including `REMOVE_CONTRACT`) and `selected_button` (`Office.Choice`). The Transport offers screen is `office().transport_offers`: `rows()`, `reasons()` (per row, `""` when the offer fits; `OVERLOADED` past the maximum capacity), `red_notes()` (per row, the red `FUEL LIMITED` note or `""`), `list` (its `ExpandableList`): `list.selected_index()` (the row under the cursor), `list.expanded_rows()` (the open rows, top to bottom), `list.scroll` (pixels the list is scrolled down), `list.more_above()` and `list.more_below()` (what the ▲/▼ markers show) and `list.cursor_in_view()` (the row or ACCEPT under the cursor lies wholly in the list's area); `details(row)` (that row's details, ending with ACCEPT; empty while closed), `on_accept()` (the cursor is on that row's ACCEPT), `notice()` (`OFFER EXPIRED` while it shows), `focus` (`TransportOffersScreen.Column`), `selected_contract()` (the Contract under the Contracts column's cursor, `null` on START LOADING), `contract_lines()`, `summary()`, `red_summary_lines()` (the summary lines whose value is red) and `start_loading_enabled()`; accepted offers are in `economy().contracts`. The Bank account screen is `office().bank_account`: `lines()` (`PILOT` and the balance), `rows()` (the transactions, newest first), `details(row)` (that transaction's breakdown; empty while closed) and `list`, read as for Transport offers; `open_bank_account()` in `scene_test.gd` opens it from the main screen. The delivery is `economy().phase` (`Economy.Phase`), `economy().loading_left`, `economy().delivery_time` (seconds since loading finished), `economy().deadline()` and `economy().delivery_left()`; the HUD timer is `hud().delivery_text()` and `hud().delivery_overdue()` (red). `scene_test.gd` has the Transport offer helpers: `open_transport_offers()`, `select_row(i)`, `listed(prefix)`, `reason_for(offer)`, `offers()`, `known_offer(passengers, cargo, time_left)`, `open_details(offer)` (selects its row and opens it, leaving the cursor on the row), `accept(offer)` (opens it, Down to its ACCEPT, Return, Yes) and `start_loading(offers)` (puts the offers in the pool, accepts them, presses START LOADING and waits for the Terminal to power off). The Terminal powers on (opening) and off (closing) with a ~0.3 s CRT effect, during which `office().powering` is true and Office input is ignored; `start()`, `choose_ship()` and `restart()` wait it out, and `wait_for_terminal()` does so elsewhere (`restart(false)` skips the wait). `dock_in_spot()` places the ship in the parking spot so it docks, which opens the "ENTER THE OFFICE?" popup: answer it (e.g. `press(&"ui_accept")` for the default No) before testing refuelling.
  - Tests extend `res://tests/scene_test.gd`. They drive the game with real input actions (`press`, `hold`, `release`), wait with `frames(n)` or `seconds(t)`, and check only what a player could observe: the lander's state, position, velocity, fuel, total mass and ship type, and the message text (`message()`, empty while hidden). `world()` is the World; `pad_x()` is the current location's pad centre x and `pad_visual_center_x()` the drawn pad's middle. A test may move to another location with `world().change_location(location)`, e.g. a `Location.new()` with its own pad centre.
  - To set up a start position, call `place(position, velocity)`: it puts the lander Flying there through `fly_from()`, the same transition the game uses. For anything else, set the lander's public state directly. For Transport offers, a test may seed the Economy with `economy().reseed(n)` (a new pool of 5 from that seed, numbered from `#001`, with a fresh 30–90 s wait for the next offer) and put a known offer in the pool with `economy().put_offer(offer)` (it adds the offer, or replaces the one closest to expiring when 7 are listed, and takes the next number). Border crossing tests seed the Lander's disturbance with `lander().rng.seed = n`. `raise_to_maximum_weight()` sets a Load (`load_mass`) that brings a full ship to its Maximum weight. `restart()` presses R and waits for the reloaded scene; since R on the Surface only teleports to the pad, it first moves a ship that's below the border into deep space. `crash_in_deep_space()` crashes the ship into the station's underside.
  - Headless runs don't render anything, so visuals and game feel need a human playtest.
