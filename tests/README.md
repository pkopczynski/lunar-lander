# Tests

How to run the tests is in the root [`README.md`](../README.md). This file is for writing them: what the runner does, and the helpers and read-outs a test uses. Why tests drive only the main scene: [ADR 0004](../docs/adr/0004-one-test-seam-the-main-scene.md).

- **Run:** `Godot --headless --path . --fixed-fps 60 -s tests/run_tests.gd` runs every test and exits non-zero if any fails. A test may call `pending(what)` for a part it can't require yet; the runner prints it under the test without failing it. In a fresh checkout, run `--import` first. `--fixed-fps 60` makes each frame one physics step without waiting for real time; the tests count physics frames, so they give the same results without it, just slower. To run only some files while working, add `-- --only=test_shipyard,test_hangar` (file names without `.gd`); run the whole suite before pushing.
- The runner loads every `tests/test_*.gd` and calls each `test_*` method on a fresh main scene. A test fails if a `check` fails, if no checks ran, or if any script error is logged while it runs.
- Every run opens on the Office, so a test that flies calls `await choose_ship()` (or `choose_ship(ShipType.MULE)` etc.) first: it puts a ship of that type in service the way a player does, then presses Escape until the Office closes, leaving the ship Docked. SPARROW 1 needs nothing; an owned ship of the type is put in service from the Hangar; otherwise one is bought in the Shipyard first, with its price added to the balance beforehand, so the balance ends as it was but the purchase is a Transaction (the newest row in the Bank account until a later one). `swap_to(type)` does the same and stays in the Office, on the main screen. The Shipyard and Hangar helpers in `scene_test.gd`: `open_tile(i)` (0 SHIPYARD, 1 HANGAR, 2 TRANSPORT OFFERS, 3 BANK ACCOUNT), `open_shipyard()`, `open_hangar()`, `browse_to(type)` (Right or Left in the Shipyard until it offers that type), `buy_ship(type)` (from the main screen: the Shipyard, BUY, Yes; returns the new `OwnedShip`, whose Ship page is then open), `open_ship_page(ship)` (from the Hangar's table), `select_action(HangarScreen.Action.SELL)` (moves to it on a Ship page and presses Return), `put_in_service()` (PUT IN SERVICE, then Yes), `leave_office()`, `hangar()` and `owned_ship(type)`. Set-up may set `economy().balance` and add an owned ship with `hangar().buy(type)` and change its `fuel` or `condition` directly. Office tests read `office()`: `showing`, `screen` (`Office.Screen`), `tile_labels()`, `selected_tile()`, `screen_title()` (`HANGAR // MULE 1`), `balance_text()` and `balance_red()` (the header's balance), `notice()` (the notice line while it shows: `MULE 1 IS IN THE HANGAR`, or a blocked item's reason, such as `Office.WRECK_IN_SERVICE` when leaving is blocked), `main_lines()` (the main screen's line under the tiles: the ship in service's name and `WRECKED` while it's a Wreck, else empty), `popup_text()`, `popup_warning()` (a confirm's red line, `THIS LEAVES YOU AT -€55 000`, or `""`), `popup` (`Office.PopupKind`: `CONFIRM` for a purchase, sale, swap or repair, `ACCEPT_OFFER`, `REMOVE_CONTRACT`, `CANCEL_MISSION`, `ENTER_OFFICE`) and `selected_button` (`Office.Choice`). The Shipyard is `shipyard()` (`office().shipyard`): `selected()` (the Ship type offered), `lines()` (its text, ratings as ■/□ blocks, then `BUY €x` and any reason), `buy_text()`, `reason()` (`""` when it can be bought), `indicator()` and `picture()`. The Hangar is `hangar_screen()` (`office().hangar_screen`): `berths_text()`, `rows()` (one per berth, columns split by two spaces, `SPARROW 1 IN SERVICE  100%  6 250 L  –  0`, then `HangarScreen.EMPTY_BERTH_TEXT`), `row` (the berth under the cursor), `ship` (the open Ship page's), `page_lines()`, `actions()` (`PUT IN SERVICE`, `REPAIR €62 500`, `SELL €125 000`; index them by `HangarScreen.Action`), `action` (`HangarScreen.Action` under the cursor) and `reasons()` (per action, `""` when it can be taken; `HangarScreen.WRECK_REASON`, `NO_DAMAGE`…). The Transport offers screen is `office().transport_offers`: `rows()`, `reasons()` (per row, `""` when the offer fits; `OVERLOADED` past the maximum capacity, `MISSION UNDER WAY` while delivering), `red_notes()` (per row, the red `FUEL LIMITED` note or `""`), `list` (its `ExpandableList`): `list.selected_index()` (the row under the cursor), `list.expanded_rows()` (the open rows, top to bottom), `list.scroll` (pixels the list is scrolled down), `list.more_above()` and `list.more_below()` (what the ▲/▼ markers show) and `list.cursor_in_view()` (the row or ACCEPT under the cursor lies wholly in the list's area); `details(row)` (that row's details, ending with ACCEPT; empty while closed), `on_accept()` (the cursor is on that row's ACCEPT), `notice()` (`OFFER EXPIRED` while it shows), `focus` (`TransportOffersScreen.Column`), `selected_contract()` (the Contract under the Contracts column's cursor, `null` on a mission row or the start button), `mission_lines()` (the mission rows, top to bottom, e.g. `DESTINATION MINE`, `START PERIOD MORNING`), `selected_mission_line()` (the label of the mission row under the cursor, e.g. `DESTINATION`, or `""`), `on_start_button()` (the Contracts column's cursor is on the start button: START, START LOADING or CANCEL MISSION), `contract_lines()`, `summary()`, `red_summary_lines()` (the summary lines whose value is red) and `start_text()` (`START LOADING`, `START` without Contracts, or `CANCEL MISSION` during a loaded mission); accepted offers are in `economy().contracts`. The Bank account screen is `office().bank_account`: `lines()` (`PILOT` and the balance), `rows()` (the transactions, newest first), `details(row)` (that transaction's breakdown; empty while closed) and `list`, read as for Transport offers; `open_bank_account()` in `scene_test.gd` opens it from the main screen. The delivery is `economy().phase` (`Economy.Phase`), `economy().loading_left`, `economy().delivery_time` (seconds since loading finished), `economy().deadline()`, `economy().delivery_left()`, `economy().loaded_at` (the local time when loading finished; a test may set it once loading has finished to fix the local times a transaction records), `economy().deadline_at()` and `economy().landed_at` (the local time of landing on the pad, counted on from `loaded_at`'s midnight); the HUD's Condition line is `hud().condition_text()` (`CONDITION 87%`) and its loss flash `hud().loss_text()` (`−6%` while it shows, else `""`); the HUD deadline is `hud().delivery_text()` (`MINE BY 14:30`, `MINE OVERDUE SINCE 14:30`) and `hud().delivery_overdue()` (red), and the HUD clock line is `hud().clock_text()` (`VALLEY  14:07`). `scene_test.gd` has the Transport offer helpers: `open_transport_offers()`, `select_row(i)`, `listed(prefix)`, `reason_for(offer)`, `offers()`, `known_offer(passengers, cargo, time_left)` (to the Valley; set its `destination` for another location), `open_details(offer)` (selects its row and opens it, leaving the cursor on the row), `accept(offer)` (opens it, Down to its ACCEPT, Return, Yes) and `start_loading(offers)` (puts the offers in the pool, accepts them, presses START LOADING, keeping the DESTINATION and START PERIOD the Office opened on, and waits for the Terminal to power off). The Terminal powers on (opening) and off (closing) with a ~0.3 s CRT effect, during which `office().powering` is true and Office input is ignored; `start()`, `choose_ship()`, `start_over()` and `recover()` wait it out, and `wait_for_terminal()` does so elsewhere (`start_over(false)` skips the wait). `dock_in_spot()` places the ship in the parking spot so it docks and waits past the 0.3 s leveling, so the "ENTER THE OFFICE?" popup is open: answer it (e.g. `press(&"ui_accept")` for the default No) before testing refuelling.
- Tests extend `res://tests/scene_test.gd`. They drive the game with real input actions (`press`, `hold`, `release`), wait with `frames(n)` or `seconds(t)`, and check only what a player could observe: the lander's state, position, velocity, fuel, total mass and ship type, and the message text (`message()`, empty while hidden). `world()` is the World; `pad_x()` is the current location's pad centre x and `pad_visual_center_x()` the drawn pad's middle. `clock()` is the planet clock. `world().sky` is the current sky reading (`ground_color`, `darkness`, `star_brightness`), taken from the clock on the next physics frame after the time changes; `world().background_color(y)` is the gradient at a height. `world().shown_stars()` is every star drawn, as `World.Star`s (`position`, `radius`, `color`; fully transparent ones left out): the surface's night stars, then the deep-space stars. `world().shown_decor(camera_center, zoom)` is every decor piece drawn (the Backdrop's ridges, farther first, with its haze bands and skyline lights, then the Moons, the clouds, the vehicles' hulls, their lights and trails, the Beacon, the Foreground, the city lights and the Activity's warning lights and movers), as `World.Decor`s: `layer` (`World.DecorLayer`: `BACKDROP` for a location's ridges or skyline, `PARALLAX` for other decor behind the surface such as clouds and flying vehicles, `FOREGROUND`, `BEACON`, `LIGHTS` for city and skyline lights and the Valley crowns' night glows), `part` (`World.DecorPart`: `LIGHT`, `GLOW`, `RIDGE`, `CLOUD`, `SILHOUETTE`, `WINDOWS` (all of a location's windows, one mesh, as its bounding box), `NEON`, `WARNING_LIGHT`, `VEHICLE_LIGHT`, `VEHICLE`, `MOON`, `TRAIL` (a Vehicle's trail of light, in `LIGHTS`), `WISP` (a cloud's translucent wisp in the Foreground), then a skyline's `SKYLINE_WINDOWS` (one mesh per depth, in `LIGHTS`), `SKYLINE_BEACON` (one mesh, in `LIGHTS`) `HAZE` (a translucent band, in `PARALLAX`) and `MOVER` (one of the Activity's slow movers, in `PARALLAX`); new parts go at the end), `has_collider`, `color` (as drawn, tinted by its own and its ancestors' modulate; a piece filled with vertex colours gives their average, tinted by its `self_modulate`: its `color` is ignored, as Godot ignores it when drawing), `opacity` (its colour's alpha as drawn), `scroll_scale` (its parallax layer's, `Vector2.ONE` outside any), `screen_outline` (its outline on screen; a mesh's is its bounding box), `screen_rects()` (a mesh of lights' rectangles on screen, one per window, in build order; empty for a polygon) and `screen_area` (its bounding `Rect2` on screen for a camera centred on `camera_center` at `zoom`, the viewport's centre being the camera's, with its parallax layer shifted for that camera). `tests/test_valley_depth.gd` has the Foreground fairness, darkness and view-coverage checks (`check_foreground_is_fair()`, `check_foreground_is_darkest()`, `check_layers_cover_the_view()`), written to run for any location. `ground()` and `mountain()` are the ground's and a mountain's visuals and `shown_color(polygon)` a Polygon2D's colour as drawn (tinted by its own and its ancestors' modulate), for checking dimming. A test may move to another location with `clock().move_to(location)`, e.g. `Location.MINE`, `Location.METROPOLIS` (its geometry constants `Location.ROOF_Y`, `STREET_Y`, `PAD_ROOF_WIDTH`, `PAD_BUILDING_LEFT`/`RIGHT`, `ANTENNA_TOP_Y`) or a `Location.new()` with its own pad centre (and, for a rooftop-like test location, its own `ground_y`, `ground_width` and `lowest_y`, or its own `backdrop` of `Backdrop.Ridge.new(top_edge, darkening)`s); the current location's terrain visuals are the `Polygon2D` children of `main().get_node("Terrain")`, read the current location's ground height with `Location.MINE.ground_y` (and the Mine's step with `Location.BENCH_STEP`), set the drift count directly with `clock().drift` (in-game minutes above the Border, e.g. `PlanetClock.DRIFT_MINUTES - 10.0` moves the location on after 5 real seconds above the Border with the surface out of view), set the local time directly with `clock().minutes` (in-game minutes since midnight; tests set half a minute past the hour they read, so whole-minute readings aren't on a boundary), and seed the clock with `clock().reseed(n)` (seeds its `rng` and starts the run over: the Valley, a new random Evening minute).
- To set up a start position, call `place(position, velocity)`: it puts the lander Flying there through `fly_from()`, the same transition the game uses. For anything else, set the lander's public state directly. For Transport offers, a test may seed the Economy with `economy().reseed(n)` (a new pool of 5 from that seed, numbered from `#001`, with a fresh 30–90 s wait for the next offer) and put a known offer in the pool with `economy().put_offer(offer)` (it adds the offer, or replaces the one closest to expiring when 7 are listed, and takes the next number). Border crossing tests seed the Lander's disturbance with `lander().rng.seed = n`. `raise_to_maximum_weight()` sets a Load (`load_mass`) that brings a full ship to its Maximum weight. R never restarts: `start_over()` loads a fresh main scene, as a fresh start of the game does (use it to compare ship types or locations from a clean state within one test). `crash_in_deep_space()` crashes the ship into the station's underside; after any crash, `recover()` presses R (Recovery) and waits for the Office to power on with the Wreck Docked at the station. A crash makes the ship in service a Wreck (`hangar().in_service.is_wreck()`), so a test that flies on after one crash calls `start_over()` or repairs it first. A hit wears the ship in service's Condition (`hangar().in_service.condition`); `tests/test_terrain_damage.gd`'s `hit_ground(falling, sideways)` drops the Sparrow onto the Valley's ground off the pad at a chosen speed. A Stranded ship (`Lander.State.STRANDED`) is recovered by pressing R and waiting for the Terminal, as `recover()` does after a crash.
- Headless runs don't render anything, so visuals and game feel need a human playtest.
